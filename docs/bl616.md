# Without a Pico: the BL616

game20k also runs without a Raspberry Pi Pico 2 W. The Companion firmware then runs on a BL616,
either the one on the Tang Nano 20K itself or a Sipeed M0S Dock on the Nano's header. Games, game
switching, menus and the stick work as with the Pico. RetroAchievements need the Pico 2 W's Wi-Fi
and are not available.

## From a release

| Setup | Cores | Firmware from `game20k-<version>-firmware-bl616.zip` |
|---|---|---|
| Tang Nano 20K alone, revision 3923 | `game20k-<version>-cores-tangnano20k-singleboard.zip` | `game20k-<version>-nano20k_v3923.bin` |
| Tang Nano 20K alone, revision 3921 | `game20k-<version>-cores-tangnano20k-singleboard.zip` | `game20k-<version>-nano20k.bin` |
| Tang Nano 20K with an M0S Dock | `game20k-<version>-cores-tangnano20k.zip` | `game20k-<version>-m0sdock.bin` |

Cores and firmware must come from the same release. The revision is printed on the underside of
the Nano. The two revisions wire the BL616 differently, so only the matching firmware works. The
cores are the same for both.

Flash the cores with openFPGALoader as described in the [README](../README.md#quick-start). Flash
the firmware with BLFlashCommand from the [Bouffalo SDK](https://github.com/bouffalolab/bouffalo_sdk)
(`tools/bflb_tools/bouffalo_flash_cube`, which also holds the graphical BLFlashCube). Run it in the
unpacked firmware zip, where each `flash-<board>.ini` names the image and its address. The port is
e.g. `/dev/ttyACM0` (Linux), `/dev/cu.usbmodem1101` (macOS) or `COM3` (Windows).

### Tang Nano 20K alone

The firmware goes to 0x40000, behind Sipeed's debugger firmware at 0x0, which must stay. The
debugger firmware starts the Companion when no computer is connected. This requires version
2025030317 or later, shown as the serial number of the board's USB debugger (System Information,
`lsusb -v` or Device Manager). Older versions must first be replaced with Sipeed's
[FPGA Partner firmware](https://github.com/MiSTle-Dev/FPGA-Companion/tree/main/src/bl616/bl616_fpga_partner).
That step writes to 0x0, which `g20k.py` never does, and some early boards cannot run it.

Unplug the board, hold UPDATE, plug it in, then run:

```sh
BLFlashCommand --interface=uart --chipname=bl616 --baudrate=2000000 --port=<port> --config=flash-nano20k_v3923.ini
```

To play, power the board through a powered USB hub on its USB-C port and plug the stick into the
hub. Some hubs only detect the stick after a full power cycle.

### M0S Dock

Wire the dock to the Nano's header as described in the
[FPGA-Companion README](https://github.com/MiSTle-Dev/FPGA-Companion/blob/main/src/bl616/README.md).
It uses the Pico's pins, so it takes the normal cores. The firmware goes to 0x0. Unplug the dock,
hold BOOT, plug it in, then run:

```sh
BLFlashCommand --interface=uart --chipname=bl616 --baudrate=2000000 --port=<port> --config=flash-m0sdock.ini
```

## From source

`g20k.py` builds and flashes both, see [BUILD.md](BUILD.md) for the tools:

```sh
python3 g20k.py firmware --bl616 nano20k_v3923       # or nano20k, m0sdock
python3 g20k.py flash --bl616 nano20k_v3923 --port <port>
python3 g20k.py build fpga/galaga_hdmi --board boards/tangnano20k-singleboard
python3 g20k.py flash fpga/galaga_hdmi --board boards/tangnano20k-singleboard
```

Like the ini files of a release, `flash --bl616` writes only the board's own address. On the Nano
alone, the BL616's console (921600 baud) comes out on pin 51 of the header.
