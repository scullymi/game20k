Flashing {project} {version} onto the Tang Nano 20K alone

{name}.bin holds every game's core at its place in the board's flash. These cores
talk to the Companion on the board's own BL616, not to a Pico or an M0S Dock on the
header. With the repository (https://github.com/scullymi/game20k), one command
downloads, checks and writes it, see docs/bl616.md there:

  python3 g20k.py flash --download {version} --board boards/tangnano20k-singleboard

By hand, write it with openFPGALoader (brew install openfpgaloader, apt install
openfpgaloader):

  openFPGALoader -b tangnano20k -f --verify {name}.bin

Gowin's programmer_cli works too, given the full path of the file:

  programmer_cli --device GW2AR-18C --run 32 --mcuFile "$PWD/{name}.bin" --spiaddr 0x000000

If it reports an error, run it once more. It must start at 0x000000: given another
address, programmer_cli erases there but writes at 0x000000.

The BL616 needs the firmware of the same version from
{project}-{version}-firmware-bl616.zip. Take the image of your board's revision,
which is printed on the underside of the Nano:
{project}-{version}-nano20k_v3923.bin for revision 3923,
{project}-{version}-nano20k.bin for revision 3921. The other one does not work.
It needs Sipeed's debugger firmware 2025030317 or later on the BL616.
FLASHING.txt in that zip says how to write it and how to check that, more in
docs/bl616.md of the repository:
https://github.com/scullymi/game20k/blob/v{version}/docs/bl616.md
